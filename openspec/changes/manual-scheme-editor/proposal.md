## Why

当前结果页只展示引擎基于快照算出的推荐方案，用户拿到的是「我们预测的价」，而不是「真实成交价」。苹果二手/国补价格波动大、地区差异明显，快照中位价与用户实际能买到的价常有偏差；用户也无法在端内做「改个价、排除某个方案、加一个我自己看到的机型」这类轻量比价。结果是：用户对推荐的可信度打折，而我们手里明明有一个「让用户回传真实成交价」的天然数据入口，却没接住。本 change 在结果页加一个「手动修改方案」入口，把前沿选项变成一张可交互比价表，同时把用户修改后的成交价作为众包数据回传影子库——既给用户一个趁手的比价工具，也给我们的保值率/价格预测模型一个持续校准的数据飞轮。

## What Changes

### 结果页新增「手动修改方案」入口与编辑器

- 结果页底部新增「手动修改方案」入口，进入一个全屏/半屏的交互比价表单。
- 表单初始内容 = 当前结果页的全部方案（前沿 + 被支配点），每行可编辑：
  - **买入价**：用户可自行修改（数字输入，校验 > 0）。
  - **购买渠道**：下拉选择（闲鱼 / 转转 / 京东国补 / 官方旗舰店 / 其他），并支持勾选「是否使用国补」。
  - **排除**：复选框，勾选后该方案不参与重算（如「不考虑 8G 内存」「不考虑持有期 > 3 年」），可按属性快捷批量排除。
  - **移入暂不考虑**：单行操作，将该方案折叠到「暂不考虑」分组（不删除，可恢复）。
- **新增方案**：用户可手动新增一行，自行输入机型/芯片/内存/存储/买入时机/买入价/持有期，参与重算。
- **撤销**：支持多步撤销（undo），并支持自动保存到本地（复用 `saved-results` 存储通道，独立 key）。
- **导出长图**：用户可将修改后的方案表导出为一张长图保存到相册，长图末尾带小程序码（`<canvas type="2d">` 渲染 + `wx.canvasToTempFilePath` + `wx.saveImageToPhotosAlbum`），便于归档与转发。
- 完成修改后，可「重新生成帕累托图与完整报告」——基于用户修改后的方案集重算前沿、推荐区间、月均成本，结果页与报告页切换到「用户修改版」并明确标注「基于用户输入价」。

### 引擎新增「按给定方案集重算前沿」能力

- 引擎新增纯函数：给定一组用户方案点（含可覆盖的买入价/持有期/机型属性）+ constants，返回重算后的 `{ frontier, dominated, recommendationRange }`。
- 该函数不重新从快照提取候选，而是在用户传入的方案集上做帕累托筛选与推荐区间截取；对用户改了买入价的方案，用引擎既有 `computeMonthlyCost` / `computePerformance` 重算月均成本与性能满足度。
- 引擎保持纯函数、零运行时依赖、三端可运行。

### 众包成交价回传（影子库 + 置信度分级）

- 修改完成或导出后，提示用户「将你的方案上传到云端，帮助修正我们的预测——越多人使用并分享成交价，预测越准」。
- 用户确认提交后，数据先写入**影子数据库**（独立集合，不直接进入快照），记录：用户修改的方案（机型/渠道/国补/买入价/持有期/提交时间/匿名标识）、对应的原始推荐方案、决策参数。
- 影子库数据**不自动**回写快照；后续经「置信度分级」流程（提交量、渠道可信度、价格离散度、与历史中位价偏离度）分级纳入数据修正流程。
- 提交成功后给用户感谢语作为情绪反馈（非金钱激励，符合个人主体工具类目合规）。

## Capabilities

### New Capabilities

- `crowdsourced-price-intake`: 众包成交价回传能力域——结果页手动修改后的方案上传到云端影子库，影子库与快照隔离，经置信度分级后才纳入数据修正流程；含提交入口、影子库写入、感谢反馈、置信度分级规则。

### Modified Capabilities

- `wx-miniapp-mvp`: 结果页新增「手动修改方案」入口与交互比价表单（改价/选渠道/排除/暂不考虑/新增/撤销/自动保存/PDF 导出），并支持基于用户修改版重算帕累托图与报告。
- `apple-value-engine`: 新增「按给定方案集重算前沿」纯函数，支持用户覆盖买入价、新增自定义方案后重算月均成本/性能满足度/帕累托前沿/推荐区间。

## Impact

- **新增代码**：
  - `miniapp/wx/pages/scheme-editor/`（手动修改方案编辑器页，或作为 result 页的子模式/半屏）
  - `miniapp/wx/services/scheme-editor-state.ts`（编辑态管理：撤销栈、自动保存、排除/暂不考虑分组）
  - `miniapp/wx/services/long-image-export.ts`（方案表长图导出 + 小程序码拼接）
  - `miniapp/wx/cloudfunctions/price-intake/index.js`（影子库写入云函数）
  - 引擎新函数 `packages/apple-value-engine/src/pareto.ts`（`recomputeFrontierFromPoints` 或同类）
  - 引擎单测：改价重算、新增方案、排除/暂不考虑后的前沿筛选
- **修改代码**：
  - `miniapp/wx/pages/result/result.ts` + `result.wxml`（新增「手动修改方案」入口、切换「用户修改版」渲染）
  - `miniapp/wx/pages/report/report.ts` + `report.wxml`（接收用户修改版数据，标注「基于用户输入价」）
  - `miniapp/wx/components/pareto-chart/pareto-chart.ts`（接收用户修改版数据源，标注用户改价点）
  - `miniapp/wx/engine-bridge/index.ts`（新增 `recomputeFromEditedPlans` 桥接）
  - `packages/apple-value-engine/src/index.ts`（导出新函数与类型）
- **现有资产复用**：
  - `saved-results.ts` 存储通道与容量策略（编辑态自动保存复用同套 `wx.setStorageSync` 模式）
  - `share-result` 云函数的「云函数以小程序身份代写云数据库、用户无需登录」模式
  - 引擎既有 `computeMonthlyCost` / `computePerformance` / `selectFrontier` / `selectRecommendationRange`（重算复用，不重写筛选逻辑）
- **协议与合规**：
  - 沿用个人主体 + 无商业化约束：感谢语为纯情绪反馈，不含金钱/积分激励；不出现导购字样；影子库写入需用户主动确认，不静默上传
  - 影子库与快照严格隔离：用户提交数据不得直接出现在他人结果页（SKILL.md 禁忌 11 的延伸——众包数据须过置信度分级才纳入）
- **依赖与基建**：
  - 小程序端长图导出用 `<canvas type="2d">` + `wx.canvasToTempFilePath` + `wx.saveImageToPhotosAlbum`；小程序码复用 `share-result` 云函数的 `qrcode` action；不引入需构建 npm 的重型库
  - 引擎保持零运行时依赖
  - 云开发新增 `price_intake_shadow` 集合，权限规则设为「仅创建者可读写 + 云函数管理端写入」
- **不受影响**：
  - skill 路径（`.agents/skills/apple-value-analysis/SKILL.md`）不变
  - 决策树流程不变（手动修改是结果页的下游动作）
  - 既有分享卡 / 保存结果 / 回看流程不变（用户修改版可作为新的保存快照，不覆盖原快照）
- **后续依赖此决策的里程碑**：M2 云开发的「数据飞轮」可基于本 change 的影子库与置信度分级流程构建离线数据修正管线；置信度分级规则后续可演进为服务端定时任务。
