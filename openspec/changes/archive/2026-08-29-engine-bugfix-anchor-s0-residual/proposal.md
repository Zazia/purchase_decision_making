## Why

2026-08-28 Mac mini 购买决策分析（预算 5000，M6 已官宣未发售场景）暴露引擎三处口径与 SOP/spec 不一致，被迫写人工后处理脚本（`scripts/mac-mini-postprocess-20260828.mjs`）修正后才能得到正确帕累托前沿。若不修引擎，今后每次「涨价发布 + 推算跑分」场景（新品官宣窗口正是本技能最高频的分析场景）都要重复人工补齐，且小程序端无法复现 skill 端的正确结论。

## What Changes

- **类型C候选排除锚定品**：`extractWaitCandidates` 对快照内全部在售机型生成「等新品后买降价老款」候选，未排除即将发布的新品本身——已官宣未发售的 M6 被当作老款，自身价被乘锚涨幅再打折，产出语义伪影候选（M6 伪影价 5211 元）。修正为识别并跳过锚定品。
- **S(0) 去除 100% 截断**：`computePerformance` 中 `Math.min(1, …)` 导致推算跑分超过实测基准的新芯片（M6 推算 21000 ÷ M5 实测 17100 = 122.8%，× 16G/256G 权重 = 104.4%）被压平到 100%。SOP performance-models.md §1.2 规则2 明文「新芯片自身系数允许 >100%」。修正为去除截断（老款系数天然 ≤1，不受影响）。
- **类型A残值施加新品发布冲击**：spec「月均成本计算」与 SKILL.md 步骤 5.4 第 4 条均要求「持有期内有新品发布时残值 MUST 施加冲击调整」，`cost.ts` 未实现（模块头注释「留给 skill 层」是 v3.8 时代决策，v4.1 起引擎已持有 releasePlan + macroContext，可确定性计算）。修正为引擎内实现。
- **附带加固**：`getCurrentNewPrice`（残值分母取值）依赖快照键插入顺序——M6 恰好排第一才返回 6999，数据重排后会静默漂移回老款官方价。修正为显式选最新代际新品条目。
- 不改变对外 API 形状（`DecisionParams` / `PlanPoint` 字段不变，新增字段均为可选或内部）。

## Capabilities

### New Capabilities

（无）

### Modified Capabilities

- `apple-value-engine`：三处计算口径对齐 SOP v4.1——①类型C候选收集范围排除锚定品（新增「锚定品识别」要求）；②性能满足度 S(0) 允许超过 100%（修订「性能满足度计算」要求）；③类型A残值冲击调整从 skill 层职责移入引擎（「月均成本计算」要求下补实现细节场景）；④残值分母取值规则显式化（「月均成本计算」要求下新增场景）。

## Impact

- **代码**：`packages/apple-value-engine/src/pareto.ts`（类型C生成、buildPlanPoint 类型A分支）、`performance.ts`（截断移除）、`cost.ts`（残值冲击参数）、`release.ts`（锚定品识别辅助、调整后冲击计算抽共享 helper）、`types.ts`（可选字段）。
- **测试**：`tests/v38-wait-candidates.test.ts`、`tests/recompute-frontier.test.ts` 需更新；新增锚定品排除、S(0)>100%、类型A残值冲击三组用例。
- **行为变化**：含「已官宣未发售新品」快照的计算结果会变化（这正是修正目标）；M6 场景引擎直出结果应与 2026-08-28 人工后处理结果一致（作为验收基准）。
- **不受影响**：无新品发布窗口的常规场景（老款系数 ≤1、无冲击调整路径）数值不变。
- **依赖**：无新依赖；小程序快照同步机制不变。
