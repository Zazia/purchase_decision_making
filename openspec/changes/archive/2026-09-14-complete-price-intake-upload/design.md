## Context

动机见 proposal.md。本次修订按用户明确选择收敛为「保存结果时一次确认、一次上传、直接消费」。「展示我的方案」实际位于 result 页点击保存后进入的 share-card 页，默认开启；onGenerate 调用 share-result/save，但仅发送 params，完整 reportData 只在本地。直接导出长图 onEditorExport 另有无确认的 save 调用，需要一并收敛。

shared_results 的 createdAt/expireAt 是毫秒数，get 在 30 天过期后删除记录；当前管线读取 price_intake_shadow 的 ISO 时间。迁移须考虑时间类型、数据源和保留期限。云端实际部署状态尚未核验。

## Goals / Non-Goals

**Goals:** 复用保存分享交互和 shared_results，一份已确认上传同时服务分享和分析；避免重复操作、重复写入和把推荐价作为新的外部样本。

**Non-Goals:** 不新增上传按钮、重算后弹窗或第三集合，不再第二次调用 price-intake；不改残值公式、扫码按参数重算或人工审核 constants 的流程。不删除可能已有的独立价格上传历史资源。

## Decisions

### D1. 唯一确认在保存分享流程

「保存结果」「保存用户修改版」继续进入分享卡页。开关只选择是否上传，不立即发送请求；点击生成且 showMyPlan=true 时，在首次上传前确认一次。默认勾选也须确认，不能把默认值视为同意。

开关说明：「上传本次方案供二维码访问，其中你填写的价格将用于分析和改进预测。」确认文案：「将上传本次方案及你填写的价格，用于分享展示和价格分析。是否继续？」按钮「确认上传」「仅本地保存」。取消则关闭开关，继续本地保存和无个人方案码的图片生成。

确认范围绑定本次保存内容指纹与文案版本。同次提交失败重试、相同内容重新生成复用确认、submissionId 和 cloudId，不弹第二个价格确认。修改所保存内容后属于新提交，重新确认，不建立全局永久授权。关闭开关只影响后续生成，不表示删除已上传记录。

退出旧 checkPriceIntakePrompt、uploadPriceIntake 和 skip_price_intake 逻辑，不增加编辑器上传入口。直接导出长图移除绕过确认的 save，采用既有无个人方案码的文字降级。这个流程比独立众包通道更贴近用户保存时的意图。

### D2. 保存快照与可消费价格一次落库

扩展 share-result/save：schemaVersion=2、submissionId、params、reportData、submittedPlans、originalPlans、consentVersion，验收显式增加 isTest。一次校验后原子写入 shared_results，服务端附加毫秒数 createdAt/expireAt/consentAt、anonId、payloadHash。支持的 consentVersion 固定对应分享和价格分析用途，不接受任意版本绕过契约。

reportData 是本次实际保存的完整结果。submittedPlans 是其中可分析的用户价格子集，可为空。重算成功时同时冻结上传上下文；之后未重算编辑不得混入旧结果。保存原始版不附另一修改版价格，重开已保存结果复用持久化上下文；旧本地缓存缺失来源时只分享，不凭结果数值推断用户改价。

完整报告页也有「保存结果」入口，须同步携带同份上下文；报告页加载时冻结自身报告，保存时不再读取可能已被其他页面替换的 globalData。保留既有 reportData.isUserModified 可选展示标记。

样本仅收集未排除、未暂缓且明确输入价格的修改/自定义方案，规范 buyPrice=editedBuyPrice ?? buyPrice，保留机型、芯片、内存/存储（可获得时）、买入时机、持有期、渠道、国补状态和来源。仍为预测价、纯推荐价或只改持有期的方案不计样本；明确输入价格时转为用户价格来源，但不称已核实成交。上传不再次扣除补贴。

originalPlans 从同次原始 frontier + dominated 按稳定源标识匹配，自定义无对照明确缺省。构造上传副本，不改变编辑器原始价与 editedBuyPrice 分离，兼容 fix-manual-price-residual-anchor。

普通推荐可以分享且 submittedPlans=[]；旧参数记录仍可读，不补造同意或价格。公开 get 继续白名单返回 params、createdAt 等现有分享字段，不暴露 anonId、用途元数据或完整分析快照；精确回放历史修改方案不在本次扩展范围。

### D3. 管线直接读取 shared_results

默认源切换为 shared_results，仅消费 v2、有支持的分析 consentVersion 且含有效用户价格的记录。普通分享、旧记录、测试记录分别统计跳过原因。价格直接读 submittedPlans.buyPrice，不从 reportData 推断。与 constants 的隔离由用途筛选和人工审核保证，无需再写第三集合；沿用 shadow-intake-pipeline 能力名和脚本路径。

复用当前分页读取与按 ID 去重，台账 ID 身份包含来源集合。createdAt 保持数值，只在展示时转 ISO，旧 ISO 水位线不能直接与新值比较。水位线继续用于审计、processedIds 防乱序重复。台账加 schemaVersion/sourceCollection；空台账升级，非空旧台账保留，用独立路径从新源重建后复核切换，不混用旧组。历史 price_intake_shadow 若存在，本次默认不双源读取。

单次提交内相同配置、渠道、国补状态、买入时机及价格的持有期变体/副本只计一个价格观测。聚合组保留配置、渠道、国补差异。普通推荐分享没有新样本是合法空态。isTest 正式统计排除，诊断按 ID 只读核对而不改正式台账。

报告生成同步使用新的结构化分组字段，不沿用旧复合键拆分位置。报告中的样本概览、渠道/国补展示、constants 现值匹配与原始推荐对照必须对应同一配置和价格口径；匹配不确定时明确标为待核对，不拿其他配置或补贴口径的价格生成修正建议。历史报告保留，新报告列出来源集合、版本与各类跳过数量；缓存继续放在 scripts/debug/，报告和台账继续使用现有产物目录及脱敏约束。

### D3a. 与已完成 data-maintenance-automation 的衔接

本次是在既有维护流程上改造数据入口与消费口径。保留 pnpm intake:report 命令，由原脚本读取 shared_results 并生成建议；保留 WX_SECRET/本地凭证、共享云 API 和环境选择方式。新增诊断/台账参数通过原脚本提供并写入使用说明，不要求使用者改用另一套维护工具。

pnpm constants:lint、pnpm constants:release 及 lint → publish → verify 编排继续复用，分析报告仍经人工复核后才修改 constants 并发布。本次以真实 constants 的 lint、发布干跑、已有失败中止/回读校验测试验证兼容，不为测试分析链路而发布真实价格。已归档的维护变更作为历史记录保留；新变更同步当前主规格与使用文档。

### D4. 分享过期与消费保留分开

分享仍 30 天有效。新 v2 记录过期时 get 只返回 expired，不因扫码删除待消费数据；旧参数记录可保留原懒清理。过期后保留记录不代表继续公开访问。

本次不增加定时任务或自动清理。维护者确认导出缓存和消费台账可追溯后再安排清理；文档明确记录保留与分享有效期的差别，避免离线读取前样本已被扫码删除。

### D5. 校验、幂等与失败恢复

客户端预检，服务端独立白名单校验：有限正数价格/持有期、合法枚举、有限参数；机型名最多 160 字符、渠道 80 字符、submissionId 64 字符、submittedPlans/originalPlans 各最多 200 项、完整业务请求最多 200 KiB。用项目真实大结果检验限额；超限明确仅本地保存，不静默截断结果。

真实引擎结果可能以空字符串表示未知芯片；契约保留这一未知值，不伪造芯片，也不因此拒绝完整普通分享。芯片字段仍必须为字符串、最多 80 字符。客户端保存精确规范化内容作为指纹，服务端使用 SHA-256；报告遇到未知配置只标待核对。

可信调用上下文获取身份，v2 缺失身份拒绝写入；只落哈希标识，原始 OPENID 不落库、不写日志。以身份和 submissionId 生成不超过 32 字符的确定性 ID，兼容小程序码 scene；白名单完整内容生成 payloadHash。事务或原子仅创建保证并发唯一，同 ID 同 hash 返回旧 ID，不同内容返回 conflict。禁止 set 覆盖已上传方案。

相同内容重新生成复用未过期 cloudId；二维码过期后需新保存确认建立新记录。save 已成功但 qrcode 或绘图失败，仅重试后续步骤，不新增记录。未勾选、取消、重算、编辑、直接导出均不得发起新 save。失败保留本地保存和图片，区分「本地已保存」「云端未成功」，在原生成按钮重试。旧 params-only save 兼容但永不纳入价格分析。

## Risks / Trade-offs

- 分享含模型推荐值 → 只消费明确来源的 submittedPlans，防止预测自我反馈。
- 编辑状态比已保存结果更新 → 冻结并持久化同版本上下文，旧缓存只分享。
- 完整快照增大文档 → 明确大小限制，超限保留本地并提示。
- v2 过期后仍保留记录 → 保持分享不可访问，运维说明已消费数据清理，本次不自动删除。
- 多次不同提交可能不是独立成交 → 保证请求幂等和记录内变体去重，报告称用户提交价。

## Migration Plan

1. 实现保存上下文、v2 校验和幂等、共享记录消费测试，不新增业务集合。
2. 查询并确认客户端环境、shared_results 和 share-result；确保客户端不能直接读完整分析文档或写库，只能经受限云函数访问。
3. 先部署兼容旧客户端的 share-result，再更新确认交互、保存请求和管线来源/台账。
4. 验收未勾选、取消、确认、保存/二维码失败重试、普通/修改版、过期读取，以及真实 isTest 记录一次入库和只读消费；核对 constants 不变。
5. README/维护文档说明两集合、唯一入口、同意用途、旧记录跳过、保留策略与台账迁移。回滚函数须保持 v2 过期不懒删除，避免回滚导致新样本丢失；不删除历史数据。
6. 同步 delta 时更新两个主规格 Purpose 与 Requirements 标题再验证归档。调试新卡点回填技能。验收区分开发者工具验证、云函数部署和客户端正式发布状态。
### 云平台调用信封兼容

云平台会在调用事件附加 `userInfo` 和 `tcbContext`（后者经真实调用确认）。入口剥离这些平台字段后再执行严格业务白名单校验；不读取、保存或返回其中的身份，身份仅来自 `cloud.getWXContext().OPENID`。其他未知业务字段继续拒绝。加入附带伪造平台字段的回归，验证记录身份和幂等键不受影响。

非法字段诊断只返回被拒绝的字段名（最多10个、每个80字符），不返回字段值、身份或内部错误栈，用于真实调用与本地DTO差异排查。
