## Context

引擎自 v4.3 起使用 `残值 = 买入价 × R(卖出机龄) / R(买入机龄)`，因此当前新品价已经不参与残值计算；但数据维护链仍保留旧时代的“残值分母”概念。`visualize-residual-curves.mjs` 将二手价除以快照中的分母后直接与“相对发布价”的理论曲线比较，并以该差值计算 MAE。Mac mini v4.8 又把这个 MAE 当成校准验收，造成定义和实现冲突。

初步静态审计得到以下边界：

- 曲线总表覆盖 18 个品类，声明口径是相对发布价。
- 当前残值报告有 70 个二手观测，分布于 9 个子品类；其中 20 个分母来自同品类在售新品、50 个来自说明文本，没有结构化的同型号同配置首发价字段。
- 报告自身已经承认理论曲线与实测点存在系统口径偏差，却仍计算偏差与 MAE。
- 只有 Mac mini 曲线带有本地校准修订记录，且 v3.9.1、v4.8 明确使用当前新品价口径；其他品类目前首先是“报告不可用于校准/来源待审计”，不能未经证据直接判定曲线常量已被污染。
- 仓库要求文档驱动；一次性审计数据和拟合中间产物必须位于 `scripts/debug/`，constants 是唯一运行时数据源，发布后必须校验云端哈希。

## Goals / Non-Goals

**Goals:**

- 建立唯一、可计算、可审计的保值率曲线定义，并使 constants、SOP、脚本、测试和报告一致。
- 将年龄贬值、当前替代价值、个人实际购入回报、配置溢价、代际冲击和宏观价格事件分开建模。
- 为 18 个品类生成分母与曲线溯源审计，只有通过数据门槛的品类才允许重拟合。
- 修复 Mac mini v4.8 的错误校准，同时避免在证据不足时用另一条未经验证的“精确曲线”替代。
- 保持引擎买入价锚定公式和对外决策 API 不变。

**Non-Goals:**

- 本变更不保证一次性为 18 个品类全部采齐高质量历史成交数据。
- 不把短期新品发布冲击、涨价锚定或缺货溢价固化进长期年龄曲线。
- 不以“曲线看起来平滑”为修改依据，也不手工指定目标节点后反向挑选样本。
- 不追改按旧模型生成的历史购买决策报告。

## Decisions

### 1. 三种价格比率严格分离

定义三个互不替代的指标：

1. **曲线观测保值率** `retention_observed = normalized_used_price / exact_launch_msrp`。分母必须是同一市场、同型号、同尺寸/芯片档、同内存与存储配置的首发官方价。只有该指标可以训练 `R_category(t)`。
2. **替代价值率** `replacement_value_ratio = used_price / current_new_same_tier_price`。它回答“旧机相对现在新品便宜多少”，用于购买比较、涨价锚定和报告展示，不参与曲线拟合。
3. **个体投资保值率** `owner_value_ratio = used_price / actual_paid_price`。它反映国补、教育优惠或促销后的个人回报，不参与品类曲线拟合。

选择首发官方价而不是当前新品价，是因为曲线的自变量是机龄；若分母随新品涨价或换代跳变，年龄效应将与宏观/代际事件不可识别。选择同配置首发价而不是统一基础款，是为了避免 16G、512G、高端尺寸的配置溢价被误当成保值率。

备选方案是继续使用当前新品价并把曲线重命名为“替代价值曲线”。否决原因是引擎需要同一代设备随年龄的相对衰减 `R(sell)/R(buy)`，替代价值曲线会随着新品定价跳变，无法稳定表达年龄衰减。

### 2. 原始事实结构化，派生指标不写回为事实

新增首发价目录和二手观测集合。首发价记录至少包含品类、代际、型号键、配置维度、地区/币种、发布日期、首发官方价、来源 URL 与验证状态；观测至少包含完整配置、观测日期、价格、成交/挂单类型、成色、样本量、来源、置信度和事件状态。

`retention_observed`、机龄、配置修正、拟合权重和偏差均由脚本生成到 `scripts/debug/`，报告从该派生数据读取。说明文本只作人类溯源，禁止正则解析为校准分母。

备选方案是在每个快照条目继续增加一个 `残值分母` 数字。否决原因是字段名继续混淆三种口径，且无法验证分母对应哪一代、哪一配置与哪个时间点。

### 3. 配置、代际与事件不再混进年龄曲线

基线曲线优先使用品类主流基础配置。非基础配置只有在存在相同代际、相近机龄的配对观测、能够估计配置流动性效应时才进入拟合；否则仅作外部验证，不通过“首发价同比例折算”强行并入。

观测按事件状态分层：`normal`、`launch_window`、`official_repricing`、`shortage_or_bubble`。基线曲线只用 `normal` 或已证明跨至少 30 天稳定且可剥离事件效应的观测；新品发布冲击和涨价锚定继续由现有事件模型处理，避免双重计价。

代际效应用留一代交叉验证检查：若拿掉某一代后曲线节点大幅漂移，该节点不得标为耐久修订。这样可以防止 M4 单一事件把整个 24 月节点拉低。

### 4. 采用单调、正则化、可交叉验证的节点拟合

保留现有标准节点和引擎线性插值接口。拟合器在对数保值率空间最小化加权误差，并加入相邻斜率二阶差分惩罚：

`Σ w_i [log(y_i) - log(R(age_i))]^2 + λ Σ (Δslope_k)^2`

约束为 `R(0)=100`、节点单调不增、末端不低于品类 floor。`λ` 通过留一代交叉验证选择，不由人工看图指定。挂单、回收报价和低置信样本降权；真实成交、精确配置、可核验首发价和多时点复核提高权重。

发布验收同时看加权 MAE、加权 MAPE、留一代误差、最大单节点变化和样本覆盖。拟合分数改善但来源口径不合法时必须失败；不能再以“错误 MAE 变小”作为通过条件。

备选方案是普通最小二乘或逐节点手调。前者可能产生非单调反弹，后者不可复现且容易过拟合，均不采用。

### 5. 每个受影响年龄区间设置耐久修订门槛

一个节点或区间只有同时满足以下条件才可正式改变：

- 至少两个独立代际；若品类尚无两个代际，必须有至少三个独立时点且跨度不少于 90 天，并标为 provisional。
- 每个受影响年龄带至少三个中/高置信有效价格观测，且至少一个为成交或可验证实付口径。
- 首发价分母全部结构化并通过同配置校验。
- 留一代/留一时点交叉验证优于生产基线，且方向一致。
- 新曲线在相邻区间没有未经数据支持的斜率突变；若存在真实结构断点，必须由事件或硬件代际证据单独说明。

用户长期观察可以提高单条观测的时间稳定性置信度，但不能替代分母正确性、跨代际覆盖和完整配置校验。

### 6. 全品类审计先分类，不自动批量改曲线

审计工具为 18 个品类输出四种状态：

- `invalid_calibration_applied`：有证据表明曲线曾用不兼容分母修改；必须回退/重拟合。Mac mini 当前属于此类。
- `invalid_evaluation_only`：曲线未确认被改写，但现有报告偏差或 MAE 使用错误口径；报告不可作为校准证据。
- `provenance_missing`：缺少曲线来源、首发价或足够观测；保留现值但标记未验证。
- `verified`：来源、分母、样本覆盖和拟合回归全部通过。

分类结果写入 `scripts/debug/residual-curve-audit.json` 和可读报告。只有 `verified` 或达到 provisional 门槛的品类可进入发布候选；审计本身不得静默改 constants。

### 7. Mac mini 采用两阶段恢复

第一阶段撤销 v4.8 的 18–48 月节点，恢复 v4.5 节点作为临时运行基线，同时明确标记 `provisional/unverified`。选择 v4.5 不是宣称它正确，而是它没有 v4.8 人工制造的 12–24 月额外断崖，适合作为重新拟合前的风险控制。

第二阶段补齐 M1/M2/M4 的同配置首发价目录，重新计算所有可用观测，按本设计拟合并交叉验证；只有通过门槛才用新节点替换临时基线。M6 当前价保留为替代价值率和发布事件模型输入，不再出现在曲线 MAE 中。

### 8. 发布和报告建立硬门禁

残值报告必须并列展示三种比率并明确名称，理论曲线只能与曲线观测保值率比较。发布流水线在 constants lint 后运行曲线审计；本次有曲线变化的品类若存在当前新品价分母、说明文本分母、缺失来源、未通过交叉验证或未更新校准 manifest，流水线必须停止。

校准 manifest 记录输入观测 ID、排除原因、拟合参数、旧/新节点、训练与交叉验证指标、生成脚本版本和时间。测试从 manifest 与结构化观测重算，不再手写“23 月必须接近 55%”之类由错误口径产生的断言。

## Risks / Trade-offs

- [正确口径会让部分品类暂时没有足够数据可拟合] → 保留现有曲线并标记 `provenance_missing/unverified`，不以低质量数据填空。
- [v4.5 也来自旧口径，临时回退不是最终真值] → 把它限定为风险控制基线，报告禁止称为已验证，并优先完成 Mac mini 正确重拟合。
- [同配置首发价尤其是 CTO 历史价格难以补齐] → 基础配置优先；无法核验的高配只作验证点，不参与拟合。
- [严格排除发布窗口样本可能丢失真实结构变化] → 原始观测全部保留，以事件层单独分析；稳定后可在满足耐久门槛时转为可校准。
- [不同代际的工艺、内存起步和产品定位变化导致单一品类曲线仍有异质性] → 用留一代验证和配置/代际标签暴露不稳定性；必要时后续拆分子品类曲线，但本变更不预先扩张曲线数量。
- [增加校准门禁会让 constants 发布变慢] → 仅当曲线或校准数据变化时执行完整拟合验证；普通价格快照更新执行结构 lint 和引用完整性检查。

## Migration Plan

1. 冻结基于现有残值报告 MAE 的曲线更新，建立全品类审计基线。
2. 新增首发价目录、观测 schema、审计和 lint；将现有 70 个点迁移为结构化观测，无法证明首发价的记录标为不可校准而非删除。
3. 撤销 Mac mini v4.8 节点并标记临时基线；重新生成报告、同步本地快照并发布云端，完成哈希验证。
4. 补齐 Mac mini 关键代际/配置首发价与有效成交观测，运行受约束拟合和交叉验证；通过门槛后发布正式曲线。
5. 按风险顺序处理其他品类：先处理已有 70 个报告点涉及的 iPhone、MacBook、iPad 子品类，再处理无观测或来源缺失的其余品类。
6. 更新 SOP、CHANGELOG 与公开技能仓库，执行 constants 全链路发布和双远程推送。

回滚策略：若新拟合或发布核验失败，保持上一版 constants 和云端快照；审计/派生文件可删除重建。不得回退到 v4.8 Mac mini 节点。

## Open Questions

无阻塞问题。CTO 历史首发价不足时按“不可校准、仅验证”处理，不需要在实施前人为猜价。
