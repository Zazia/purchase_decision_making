## Why

`BRAINSTORM.md` 在「小程序化」一节并列写了三条路径（A 纯前端 / B 前端+云 / C Agent 驱动）、两套 MVP 策略（MVP-0 web-view 套壳 / MVP 原生）、五个目标平台，但没有给出可执行的方向收敛。同时在第九节留下「主体选型」未决策项，而第六节合规预警已指出该决策会反向决定哪些功能能做、哪些不能。

本 change 收敛这两层悬而未决的选择，给出 5–10h/周约束下的最快可行路径，并把「个人主体 + 暂无商业化」从口头倾向固化为产品行为契约。**现在做这个决策是因为主体类型不可平滑迁移**——拖到 MVP 跑通再换主体意味着用户与分享记录全部归零，必须在动手前定死。

## What Changes

- **架构路径定为 B**（前端 + 微信云开发），但 **MVP 阶段不启用云开发**：先用打包快照（月更版本号）跑前端，云函数周更价格放 M2。
- **跳过 MVP-0 web-view 套壳**：web-view 沙箱限制 canvas 导出和原生分享按钮，验证不了「分享卡裂变」这一核心假设；用「小红书发帕累托图 + 文末挂 GitHub」作为 0 代码验证路径替代。
- **抽离 `apple-value-engine` TS 库**：把 `constants.json` 数据访问 + 帕累托计算逻辑从 skill 中抽成独立 npm 包，skill 与小程序共用同一份引擎，避免两套逻辑漂移反噬「标准」定位。
- **MVP 形态定为微信原生小程序**：决策树表单（品类→预算→持有期→新品/二手→性能地板）+ 引擎计算 + 帕累托可视化 + **分享卡**（1080×1440 竖图，含用户预算/推荐方案/前沿缩略图/小程序码）。分享卡是核心功能，非附加。
- **主路径退出 LLM**：核心推荐走确定性计算；「不确定/帮我选」分支预留 LLM 入口但 MVP 不实现。
- **主体选型定为个人主体 + 暂无商业化运营**：放弃微信支付、电商类目、京东联盟分销、B 端订阅、付费功能。**理由**：决策框架的独立性与可信度本身就是产品的差异化壁垒，无商业化状态对此有正向作用；同时省下主体迁移的沉没成本。
- **跨端（抖音/支付宝/京东/Taro/uni-app）推迟到引擎稳定之后**：不在 MVP 阶段承担跨端框架适配成本。

## Capabilities

### New Capabilities
- `apple-value-engine`: 从 skill 抽离的 TS 计算引擎库，封装 constants.json 数据访问、保值率插值、性能满足度计算、月均成本计算、帕累托前沿筛选。skill 与小程序共用，未来 B 端 API 也基于此。
- `wx-miniapp-mvp`: 微信原生小程序前端能力域，覆盖决策树引导表单、引擎结果展示、帕累托图渲染（ec-canvas）、分享卡生成与原生分享。
- `data-snapshot-bundling`: MVP 期的数据更新机制——constants.json 打包进小程序版本号，月更节奏，定义快照版本字段、过期提示、未来向云开发周更升级的接口预留。
- `non-commercial-stance`: 个人主体 + 无商业化运营的产品行为契约——明确不做微信支付、不挂分销链接、不申请电商类目、不提供付费功能；定义此约束如何影响功能边界与未来迁移路径。

## Impact

- **新增代码**：
  - `packages/apple-value-engine/`（TS 库，npm 包形态，skill 通过远程引用或本地 link 共用）
  - `miniapp/wx/`（微信原生小程序工程目录）
  - 分享卡生成模块（canvas 2d 离屏渲染）
- **现有资产复用**：
  - `.agents/skills/apple-value-analysis/constants.json` 作为引擎唯一数据源
  - `.agents/skills/apple-value-analysis/SKILL.md` 中的帕累托算法逻辑作为引擎实现参考
  - `METHOD.md` 作为方法论锚点，小程序文案与报告表述需与其一致
- **协议与合规**：
  - 小程序代码沿用 CC BY-NC 4.0（与仓库一致）
  - 个人主体小程序不能挂京东联盟/电商类目，分享卡与结果页**不得出现**「推荐购买」「下单」等导购字样，统一用「性价比分析」「非劣方案」表述（呼应 BRAINSTORM 第六节合规预警）
  - web-view 不使用，无需 ICP 业务域名备案
- **依赖与基建**：
  - 新增微信开发者工具 + 微信小程序 AppID（个人主体）
  - 新增 Node.js 工具链（uv 仅用于 Python 侧的 skill 维护，TS 侧用 pnpm/npm）
  - 不引入云开发计费项；M2 升级时再评估
- **不受影响**：
  - 现有 skill（`.agents/skills/apple-value-analysis/`）继续独立可用，引擎抽离后改为调用引擎，对外行为不变
  - `METHOD.md` / `METHOD_EN.md` 不变
  - 双仓库同步策略（GitHub + Gitee）不变
- **后续依赖此决策的里程碑**：M2 云开发、M3 用户数据上传、M4 多品类对比，均在本 change 之外单独提案。
