# shadow-intake-pipeline Specification

## Purpose

直接消费 shared_results 中具有有效分析授权的用户价格，按配置和价格口径去重聚合，生成供人工审核的价格建议报告。以来源和记录 ID 台账保证可重复运行，排除旧分享及测试记录，不自动修改 constants。

## Requirements

### Requirement: 影子库增量导出

管线 SHALL 通过既有云开发服务端 HTTP API 直接分页读取 shared_results，以来源集合和记录 ID 去重。价格消费 MUST 限于有支持的版本与价格分析同意、且有有效用户价格子集的新分享记录；旧 params-only、普通推荐分享、测试记录 SHALL 记录跳过原因，不补造样本。管线 MUST NOT 为新数据再读取或写入 price_intake_shadow。数值 createdAt SHALL 按毫秒时间处理，禁止与旧 ISO 水位线直接比较。凭证缺失、接口失败或集合缺失 MUST 明确报错、非零退出且不改台账；已建空集合 SHALL 正常空跑。原始导出缓存 MUST 位于 gitignore 目录。

#### Scenario: 首次读取共享记录

- **WHEN** 新来源台账为空并执行管线
- **THEN** 分页读取 shared_results，仅符合版本、同意与价格条件的记录进入统计，其他记录说明跳过原因

#### Scenario: 增量导出不重复统计

- **WHEN** 上传新分享后重复运行管线
- **THEN** 新记录仅消费一次，已处理 ID 不重复统计，乱序时间不导致新 ID 被遗漏

#### Scenario: 导出失败保护台账

- **WHEN** 云端读取失败、凭证缺失或 shared_results 不存在
- **THEN** 指明原因并非零退出，既有台账保持不变

#### Scenario: 无新增样本

- **WHEN** 集合为空或只有旧参数分享、普通推荐及测试记录
- **THEN** 正常报告无新增价格样本，并区分各跳过原因

#### Scenario: 时间类型正确

- **WHEN** 新分享 createdAt 为毫秒数且现有旧台账水位线是 ISO 字符串
- **THEN** 使用新来源台账处理毫秒时间，不直接比较不同类型水位线

### Requirement: 聚合与置信度分级

管线 SHALL 按品类、机型配置、买入时机、渠道与国补状态对有效用户价格分组；配置 SHALL 包含可获得的芯片、内存、存储，未知值不得伪造。单次分享中同配置、渠道、国补状态和价格的持有期变体及复制方案 MUST 只计一个价格观测。置信度 SHALL 继续参考提交数量、价格偏离、离散度与渠道因子；分级 SHALL 至少区分可纳入与样本不足/置信度低。未达标样本 MUST 保留用于累计，不得直接丢弃。输入价 MUST 描述为用户提交价，不声称已核实成交。

#### Scenario: 高置信度组合标记可纳入

- **WHEN** 某配置及渠道组合去重后样本达到既定阈值且偏离、离散度达标
- **THEN** 报告标记可纳入，给出样本数、中位价与分级证据，仍需人工复核

#### Scenario: 低置信度组合标记样本不足

- **WHEN** 某组合仅有 2 个样本或价格离散度过大
- **THEN** 标记样本不足或置信度低，保留累计样本，不给出直接发布建议

#### Scenario: 多持有期只计一次

- **WHEN** 一次分享中包含同一用户价格的 1、2、3 年方案和复制副本
- **THEN** 原始上传保留持有期信息，该价格观测只计一次

#### Scenario: 价格口径不能混组

- **WHEN** 两个方案配置、渠道或国补状态不同
- **THEN** 不合并为同一聚合价格组

### Requirement: 修正建议报告

管线 SHALL 每次运行在既有报告目录生成日期命名的 Markdown 建议报告，并输出路径。报告 MUST 包含来源集合和版本、本次新增价格观测、各类跳过数量、配置/渠道/国补分组与分级证据，以及可纳入组合的「用户提交价中位数 vs constants 现值」和原始推荐对照。现值匹配 MUST 保证配置与价格口径可比，无法确定时 SHALL 明确标记待核对，不得生成错误配置的修正建议。历史报告 MUST 保留。报告 MUST 不含身份标识，MUST 仅供人工审核，管线 MUST NOT 修改 constants；审核后的发布 SHALL 继续使用既有维护流程。

#### Scenario: 产出报告

- **WHEN** 新分享记录消费与分级成功
- **THEN** 在既有目录产出含来源、分组证据、跳过统计和价格对照的报告并输出路径

#### Scenario: 价格口径不可比

- **WHEN** 无法匹配相同配置或无法确定国补口径一致的 constants 价格
- **THEN** 报告标记待核对，不使用其他配置或不明口径的价格计算修正建议

#### Scenario: 禁止自动回写

- **WHEN** 有组合达到可纳入门槛
- **THEN** 仅输出建议，经人工审核修改 constants 后再由既有校验、发布和回读核验流程处理

#### Scenario: 无新数据空跑

- **WHEN** 没有新的有效用户价格
- **THEN** 正常退出，报告说明无新增价格样本并显示跳过原因及已有累计摘要

### Requirement: 消费台账

管线 SHALL 维护可审计的消费台账，记录版本、来源集合、运行时间、已处理 ID、时间水位线、处理及跳过数量、分组累计和分级结论。台账 MUST 支持重复运行不重复统计，且不得把旧 price_intake_shadow 来源的水位线或分组静默混入 shared_results。空台账 SHALL 可升级；非空旧台账 SHALL 保留并明确要求在独立路径重建新来源台账，复核后再切换。

#### Scenario: 台账记录运行

- **WHEN** 一次成功消费完成
- **THEN** 台账保存来源 shared_results、运行摘要、已处理记录及分组结论，可追溯且不含匿名身份值

#### Scenario: 非空旧台账迁移

- **WHEN** 管线发现非空旧来源或旧分组格式台账
- **THEN** 保持原文件不变，提示以独立台账路径重建，禁止默默混组

### Requirement: 报告脱敏

报告与台账 MUST NOT 包含记录中的匿名标识（`anonId`）或其他可关联个人的字段。本地原始导出缓存 MUST 处于 gitignore 目录，MUST NOT 入库。

#### Scenario: 报告无个人标识

- **WHEN** 报告生成
- **THEN** 报告全文不出现 anonId 值，仅使用机型/渠道/价格等聚合维度

### Requirement: 测试隔离与共享记录诊断

正式统计 MUST 排除 isTest 标记记录并记录跳过数；诊断模式 SHALL 按共享记录 ID 验证用户价格、原始对照及同意版本而不改正式台账。报告与台账 MUST NOT 输出 anonId 或其他身份值，MUST NOT 自动回写 constants。

#### Scenario: 测试记录不进入正式统计

- **WHEN** 管线读到已确认上传的测试分享记录
- **THEN** 正式价格样本不增加，报告列出测试跳过数量

#### Scenario: 直接消费同一记录

- **WHEN** 对页面上传返回的 shared_results ID 执行诊断
- **THEN** 能核对用户价格 2500 与原始价 2700，诊断不依赖第三集合，不改台账或 constants
